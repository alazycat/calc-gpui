# 运算符结合性与除零语义

统一 standard / scientific / programmer 三个求值器时，我们决定：幂运算符（`^`、`xʸ`、`logᵧ`、根号）按**右结合**求值，其余运算符左结合；除零一律产生显式的 `DivideByZero` 错误，不再依赖浮点 `inf` / `NaN` 当控制流。

两个决定都是**故意的行为变化**，不是为了修 bug：

- 右结合让 `2^3^2` 得 `512`（数学惯例），而旧实现左结合得 `64`。左结合符合「从左到右」的直觉，但违反数学记法，且幂的书写习惯比编程习惯更常见于计算器场景。
- standard 模式原先除零会显示「错误」并让 `inf` 参与后续运算；改为显式错误后，三个模式的提示文案统一为「不能被零除」，且错误不会静默污染后续结果。

任何「把 `^` 改回左结合」或「让除零回到 `inf`」的改动都应视为推翻本 ADR，需要重新讨论，而不是当作 bug 修复。

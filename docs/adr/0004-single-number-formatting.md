# 数值显示只有一套规则

`src/shared/number.rs` 是唯一的显示规则：保留 14 位有效数字消除浮点误差、`|x| >= 1e15` 或 `|x| < 1e-9` 自动用科学计数法、非有限值显示「无效输入」。两个入口，区别只在**谁决定用不用科学计数法**：`format_plain` 给没有 F-E 开关的调用方（标准模式、换算器），`format_value(x, scientific)` 给有开关的（科学模式）。

标准模式原来的 `format_number`（四舍五入到 10 位小数）已删除。这是**故意的行为变化**：旧规则把 `1e-12` 显示成 `0`，把 `1e20` 铺成 21 位整数，同一个数在标准与科学模式下文本不同。变化清单：`1÷3` 从 `0.3333333333` 变 `0.33333333333333`，`1e20` 变 `1e+20`，`1e-12` 变 `1e-12`。

与之配套，非有限值一律进错误态（`CalcError::InvalidInput`），不再把「错误」两个字塞进显示屏。旧实现里 `√(-9)` 显示「错误」但 `is_error()` 为假，接着按 `4` 会把显示拼成「错误4」；现在按 `4` 会从错误态重新开始。溢出（`1e308 × 10`）同理。

有两处**故意不统一**：程序员模式的进制显示（`DEAD BEEF`、按补码解释符号）和绘图坐标轴的刻度（小数位数跟随步长，相邻刻度不能显示成同一个数）。它们的目标与「计算器显示屏上的一个数」不同，硬套同一规则会把刻度搞坏。

想在某个模式里「为了好看」再写一个 formatter，就是在推翻本 ADR。先确认共享规则确实错了，再改 `shared/number.rs` 一处。
